# QQ 桥：实时画面与截图（A + B）

在 QQ 里发任务给 agent，然后**看着它操作浏览器**、或者让它**把当前画面截图发到聊天**。

命令总览见 [COMMANDS.md](COMMANDS.md)；升级见 [UPGRADE.md](UPGRADE.md)。

## 两件事

| | 做什么 | 你得到 |
|---|---|---|
| **A** | 任务开始时回执里带上「实时画面」链接；桥在任务期间把画面推给面板 | 手机/电脑打开链接，在面板里看 agent 当前页面 |
| **B** | 任务结束时（或你发 `/shot`）把当前页面截图发进 QQ 聊天 | 直接在聊天里看图，不用打开任何链接 |

## 配置（`.env`）

```ini
# 面板地址（桥把画面推给它；面板和桥是两个进程，不推的话面板看不到桥的浏览器）
QQBOT_DASHBOARD_URL=http://127.0.0.1:8080
# 推帧/取图鉴权：面板与桥填同一个值
QQBOT_DASHBOARD_TOKEN=换成一串随机字符
DASHBOARD_FRAME_TOKEN=换成一串随机字符     # 与上面同值
# 给你点的链接（留空 = 用 QQBOT_DASHBOARD_URL）
QQBOT_LIVE_URL=
# 任务结束/收到 /shot 时把截图发到 QQ
QQBOT_SEND_FRAME=true
# 备用上传通道：QQ 服务器能抓到的公网图片地址（内网地址它抓不到）
QQBOT_PUBLIC_FRAME_URL=
# 任务期间推帧间隔（秒，最小 0.5）
QQBOT_FRAME_PUSH_SECONDS=2.0
```

面板要起来（`MY_AGENT_WEB_UI=1` 才提供网页）：

```bash
MY_AGENT_WEB_UI=1 python -c "from dashboard.server import start_server; start_server('127.0.0.1', 8080)"
python -m agent.qqbot            # 另开一个进程跑桥
```

## 聊天里怎么用

| 输入 | 效果 |
|---|---|
| 任意任务 | 回执带实时画面链接；任务期间画面持续推到面板；结束再发一张截图 |
| `/shot` | 立刻把当前画面截图发给你（浏览器没开就明确说没有画面） |
| `/help` | 命令列表 |

## 截图是怎么发出去的（两条通道，自动选）

1. **base64 直传**：把截图的 base64 直接传给 QQ 的上传接口。
   ⚠️ 官方 SDK 只暴露了 URL 形式，`file_data` 字段**未经文档确认** → 代码先试这条，失败自动降级。
2. **公网 URL**：把 `QQBOT_PUBLIC_FRAME_URL`（能被 QQ 服务器抓取的图片地址）交给平台去抓取。
   面板也提供这个地址：`http://<面板地址>/api/frame.png?token=<token>` —— 但**它必须公网可达**，
   否则 QQ 服务器抓不到（这也是为什么不建议把面板裸开公网，见下）。

两条都失败时会明确告诉你失败原因，不会静默丢弃。
`python -m agent.qqbot --probe-media` 打印当前通道配置；真正验证在会话里发一次 `/shot`。

## 安全（重要）

- 面板**没有任何登录鉴权**（只有 Origin 白名单），取图端点靠 `DASHBOARD_FRAME_TOKEN` 保护。
- 所以：**优先**让面板绑 `127.0.0.1`，用 SSH 隧道访问：
  ```bash
  ssh -L 8080:127.0.0.1:8080 ubuntu@<服务器>
  ```
  这样 A 的链接在本机可用，且端口不暴露。
- 若确实要让手机直接访问：加一层反代 + Basic 鉴权 / 只放自己 IP 的云安全组，并**务必**设置
  `DASHBOARD_FRAME_TOKEN`（否则取图端点对全网开放，等于把你的浏览器画面公开）。
- 面板里的浏览器 profile 含**登录态 cookie**：把它开在公网等于把会话交出去。

## 平台限制（如实说）

QQ 机器人的**主动消息额度极稀少**（官方：单聊/群聊各每月 4 条）。所以：

- 「你发消息 → 它回复」是**被动回复**，额度充足，A/B 都在这条路径上 ✓
- 「它自己隔一段时间主动推给你」会消耗主动额度，**不可依赖** ✗

因此设计成：任务回执带链接（被动）、`/shot` 你随时要图（被动）、任务结束发一张（被动窗口内）。
